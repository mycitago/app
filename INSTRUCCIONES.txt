MYCITAGO · SERVICIOS HOTFIX V2
==============================

CAUSA CONFIRMADA
----------------
El negocio CLINICA EL DIENTE tiene:
- business_category_id = dental
- business_category_locked = true
- category_name = Dentista

El Hotfix V1 no consideraba business_category_id como código directo.
Por eso no detectó correctamente "dental" y el selector de Servicios
siguió permitiendo mezclar Barbería/Uñas.

QUÉ CORRIGE V2
--------------
1. Lee business_category_id = "dental" directamente.
2. Si business_category_locked = true:
   - fuerza el selector a Dentista;
   - bloquea el selector;
   - fuerza renderServiceTemplates("dental");
   - bloquea cualquier intento de aplicar una plantilla ajena al giro;
   - bloquea también creación por lote de otro giro.
3. Evita duplicados:
   - activo => Editar;
   - inactivo => Reactivar el mismo ID;
   - nuevo => Crear.
4. Hace una consulta final a services antes de cada INSERT.

SUBIDA A GITHUB
---------------
Reemplaza el archivo:
js/admin-services-template-guard.js

por el archivo V2 incluido en este ZIP.

NO cambies admin-services.js.
NO ejecutes SQL para instalar este hotfix.
NO borres filas todavía.

VERIFICA QUE admin/servicios.html YA CONTENGA:
<script src="../js/admin-services.js"></script>
<script src="../js/admin-services-template-guard.js"></script>

Si ya agregaste esa línea con V1, NO debes volver a agregarla.

PRUEBA
------
1. Recarga fuerte: Ctrl+F5.
2. Entra a Servicios.
3. "Tipo de negocio" debe mostrar Dentista y quedar bloqueado.
4. No deben aparecer plantillas Barbería ni Uñas.
5. Valoración dental y Limpieza dental deben mostrar Editar si están activas.
6. Desactiva una dental y confirma que la plantilla cambie a Reactivar.
7. Reactívala y verifica en Supabase que conserve el mismo ID.

IMPORTANTE
----------
Las filas contaminadas ya existentes no se borran con este hotfix.
Primero validamos que ya no puedan volver a crearse.
Después limpiamos los registros incorrectos una sola vez.
